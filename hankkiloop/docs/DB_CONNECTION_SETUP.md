# 프런트–Supabase 연결 적용 안내

## 적용 방법

1. 개발 서버를 Ctrl+C로 종료합니다.
2. 압축 안의 `est-fridge-app/hankkiloop` 내용을 현재 `C:\Users\우성한\Downloads\est-fridge-app\hankkiloop`에 덮어씁니다. 폴더 전체를 삭제하거나 한 단계 안쪽에 추가하지 마세요. 기존 `.env`, `.env.local`, `.git`은 그대로 둡니다.
3. Supabase SQL Editor에서 `supabase/migrations/20260916_fridge_connection.sql` 내용을 실행합니다. 기존 DB에 추가 적용하는 SQL이며, 전체 초기 스키마는 다시 실행하지 않습니다.
4. 아래 명령어로 실행합니다.

```powershell
cd "C:\Users\우성한\Downloads\est-fridge-app\hankkiloop"
npm install
npm run dev
```

로그인/선호 저장이 이미 정상이라면 이전 migration은 재실행할 필요 없습니다. cooking_frequency 또는 recipe_suggestion_enabled 컬럼 누락 오류일 때만 `20260915_auth_preferences.sql`을 먼저 적용하세요.

## 연결 범위

| 화면/동작 | DB |
| --- | --- |
| 닉네임 | profiles.display_name |
| 선호·비선호·알레르기 | user_preferences의 preferred_tastes / excluded_ingredients / allergies |
| 냉장고 목록 | inventory_overview (inventory_items + inventory_dates) |
| 재료 등록 | hk_register_inventory_batch: 재고와 날짜 함께 저장 |
| 상세 → 남은 양 수정 | hk_edit_inventory_item: 이름·수량·보관 장소·소비기한 |
| 냉장고에서 제거 | 확인 후 discarded 상태와 수량 0으로 변경, 이력 보존 |
| 요리 완료 후 차감 | hk_change_inventory_batch + 기존 change_inventory_quantity |
| 홈 현황 | 실제 재고 개수·장소별 개수·기한 임박 재료 |

새 계정은 재고 0개로 표시합니다. 데모 재고를 DB로 자동 복사하지 않습니다. 재료마다 구매일·소비기한·보관 장소를 별도로 보존하며 소비기한은 제품 표시를 직접 입력합니다. 상세의 예시 AI 신선도 점수는 제거했습니다.

## 실제 확인 순서

1. 마이페이지에서 비선호 ‘오이’, 알레르기 ‘땅콩’을 각각 입력하고 Enter → 설정 저장 → 새로고침 후 구분되어 유지되는지 확인.
2. 냉장고 → 직접 재료 추가 → 대파 240g, 냉장, 구매일과 제품 소비기한 입력 → 등록.
3. 홈 재고 수와 냉장고 목록 반영 확인. 새로고침·재로그인 후에도 유지되는지 확인.
4. 상세 → 남은 양 수정 → 200g으로 변경하고 보관 장소·소비기한 수정 → 새로고침 확인.
5. 같은 이름으로 다른 구매일·소비기한을 등록하면 별도 항목인지 확인.
6. 냉장고에서 제거 → 폐기 처리. 목록에서 사라지고 DB의 status=discarded, quantity=0인지 확인.
7. 다른 계정으로 로그인해 기존 사용자의 재료가 보이지 않는지 확인.

## 데이터 처리

- 개·모·대는 DB ea, 팩은 pack으로 저장합니다. g/ml도 그대로 저장합니다. 근거 없이 g↔개수 단위를 환산하지 않습니다.
- 레시피의 재료 이름과 단위가 대응하는 재고만 보유량에 합산합니다. 예: 대파 ‘대’ 레시피에 대파 ‘g’ 재고를 임의 환산하지 않습니다.
- 같은 이름·단위는 합산하고, 여러 묶음 차감은 기한이 빠른 순서로 배분합니다. 미확인 재료는 차감에서 제외합니다.
- 동일 화면에서 등록/차감을 재시도하면 요청 ID를 재사용합니다. 통신 오류 후 새로고침했다면 새 등록 전에 냉장고 목록을 확인하세요.
- 다른 화면에서 변경된 재고를 수정하려 하면 새로고침을 요청합니다.
- 읽기 실패는 빈 냉장고가 아니라 오류와 다시 불러오기 버튼으로 표시합니다.
- 다른 탭에서 돌아오면 다시 조회합니다. WebSocket 기반 실시간 구독은 추가하지 않았습니다.

## 아직 연결하지 않은 기능

레시피 목록·추천, 장바구니 상품/수량, 저장한 레시피, AI 채팅, OCR, 알림 읽음 상태는 예시 또는 화면 상태입니다. 장바구니 재료의 냉장고 등록은 DB에 저장하지만 shopping_items 외래키 연결은 장보기 연동 때 추가합니다. 알레르기 저장은 구현했지만 예시 레시피의 알레르겐 판정·차단은 포함하지 않습니다. 알림 설정의 DB 저장은 기존 기능을 유지합니다.

## 검증 결과

- 빌드 성공, lint 경고·오류 없음, 테스트 25개 통과.
- 로그인·선호, 알레르기 저장 필드, 빈 DB/날짜 미등록, 단위 불일치, 초과 차감, 비동기 등록 오류·중복 클릭 방지 검증.
- 원본 전체 스키마와 추가 SQL을 로컬 PGlite(PostgreSQL)에 적용해 소유자 RLS, 등록 원자성·중복 방지, 수정 충돌, 차감 재시도·실패 롤백, 타 계정 접근 차단, 폐기 처리 검증.
- 실제 Supabase에는 접속하지 않았으므로 SQL 적용과 실제 계정 저장은 위 절차로 확인해야 합니다.
